Open-source distributed job engine · self-hosted

Jobs that outlive their workers.

CLUSTERX runs every job at least once. Leases and fencing make sure a worker that vanished, and then came back, cannot overwrite what happened while it was gone.

Explore the demo Read the quickstart

At-least-once, not exactly-once: a handler can run twice, so side effects need to be idempotent. The engine guarantees only that the database never records a stale result.

The eight steps

  1. AdmitCommitted before the API answers.
  2. ClaimAttempt 1, lease generation 1.
  3. RenewWorker A extends its lease.
  4. SilenceWorker A stops renewing.
  5. ExpireLease ends on the database clock.
  6. RecoverBack to queued; worker B claims it.
  7. CommitWorker B's result is accepted.
  8. FenceWorker A's late report is rejected.

Three things it does

Small surface. Stated guarantees.

01 / Admission

Acknowledged means committed.

A job gets a success response only after its transaction commits in PostgreSQL. A coordinator restart does not lose acknowledged work.

POST /jobs → 201 after commit

02 / Execution

Leases and fencing.

Every claim creates an attempt and a lease generation in one transaction. Reports from a stale attempt, generation, or revoked credential are refused.

attempt + generation + incarnation

03 / Operation

A console that shows persisted state.

Queue age, workers, attempts and events come from the database. When the live channel drops, the screen says so and reconciles from a snapshot.

live hint → snapshot → render

Architecture

One coordinator, one database, workers that pull.

Workers never touch the database. They ask the coordinator for work and report back over authenticated gRPC.

  1. Layer 1

    Browser

    Console and public site over HTTPS. Holds no API or worker tokens.

    session cookie only

  2. Layer 2

    Next.js server

    Human sessions and the server-side proxy. Signs short-lived service assertions.

    trust boundary

  3. Layer 3

    Go coordinator

    REST, gRPC, scheduler and authorization on every call.

    enforces roles

  4. Layer 4

    PostgreSQL

    The only authoritative store for jobs, attempts, leases and events.

    single source of truth

  5. Layer 5

    Workers

    Trusted, precompiled handlers. Pull work, renew leases, report results.

    credential per worker

The worker-failure story

What happens when a worker dies mid-job.

The same eight steps, in plain terms: no retry is hidden, no result is overwritten.

  1. t+00 s

    Claimed. Worker A holds attempt 1 under a 30 s lease.

  2. t+30 s

    Lease expires. The database clock decides, not the worker. Attempt 1 counts against the job's budget.

  3. t+32 s

    Retried. With budget left the job goes back to the queue; worker B claims attempt 2.

  4. t+34 s

    Committed. Worker B's result is recorded with its attempt and generation.

  5. t+41 s

    Rejected. Worker A reports late. The result is refused and a diagnostic event is kept. The job still says succeeded.

Limitations and questions

What it does not promise.

Is processing exactly-once?

No. Execution is at-least-once. If a worker loses its lease while a handler is still running, the handler may run again on another worker. The database only records a result from the current attempt, so make external side effects idempotent.

Can the engine stop a handler that ignores cancellation?

No. Deadlines and cancellation are cooperative: they stop the engine from accepting results, not a goroutine from running. Handlers should honor their context.

What if the coordinator goes down?

There is one coordinator. While it is down, no new claims or reports happen; workers must not assume a lease still holds. Processing resumes from PostgreSQL when it returns.

Is job order strict FIFO?

No. Eligible jobs are claimed by priority, due time and creation time, but concurrent claimers can see rows out of strict order.

Does the demo show real data?

No. The public demo is seeded fixture data in your browser, with no connection to a running system. The real engine runs locally with Docker Compose.

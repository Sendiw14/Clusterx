## Answers to the author's reviewer questions (HANDOFF-M1-BE-01)

1. Success after committed cancel ⇒ `canceled`: consistent with §5 (focus 1 PASS). Fix the reply contract (RV01-03) and record the discarded success (RV01-08).
2. EPQ with unlocked joined rows: acceptable for 1.0 only with the corrected, quantified bound (RV01-04). "Committed before statement start ⇒ observed" is true; the stated window is not.
3. Cancel `SELECT … FOR UPDATE` before CAS: correct; it makes the branch deterministic and is load-bearing for the current error handling (mutant M8 killed).
4. Deferred composite FK: sound; deferral not needed for retention (see focus 3).
5. `jti` in-memory cache: acceptable only with the restart window documented or persisted (RV01-12). Session DB re-check per request: correct, add `sid`↔`sub` binding (RV01-11). Stream re-check ≤ 30 s: fine for sessions, missing for tokens (RV01-13). Session-only token/credential management: correct and consistent between permissions.md and OpenAPI (`security: [serviceAssertion]` on all `/tokens*` and `/worker-credentials*` ops).

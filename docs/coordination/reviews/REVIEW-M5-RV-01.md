### Rulings on the author's judgement calls (HANDOFF-M5-BE-02)

| Call | Ruling |
|---|---|
| SDK treats `codes.Internal` as transient (Claim, Heartbeat, Register, renew, report) | **ACCEPTED.** Renew and report retries stay bounded by the worker's monotonic lease validity (`worker.go:357-361`, `:392`). A report retry is safe because a report that already committed is answered `already_final`. Claim and Heartbeat back off to at most 5 s. The cost is that a deterministic coordinator bug now shows up as a logged retry loop instead of a crash loop, which is acceptable. The test kills the mutant (D9). |
| A deregistered id registers a **new** worker row | **ACCEPTED with conditions.** This is safe for fencing: the drained row stays `deregistered` and is never resurrected. The integrator wrote "rejoining needs a new worker_id (delete the id file)", but here the server assigns the new id with no operator action. The operator-visible consequences must be stated for M6. (a) An operator drain of a supervised worker (`restart: always`, k8s) behaves like a rolling restart: the process comes back as a new active row. **To keep a host out, revoke its credential.** The console drain UI and docs must say so. (b) Every graceful restart (SIGTERM → self-drain → deregister) now creates a new `workers` row. CR-M5-01 #4's persisted id now only saves the liveness wait after a *crash*. (c) Condition: **RV5R-01 must be fixed.** The "new row" path skips the one-live-worker-per-credential check. Integrator: please ratify this wording against your decision. |
| Feed cursor = previous poll's `pg_current_snapshot()`; `job_events.txid xid8 DEFAULT pg_current_xact_id()` | **ACCEPTED: correct, and better than the ticket's example.** A bigint identity or sequence is assigned before commit and is not commit-ordered, so it would bring back the late-commit miss. Correctness: (1) `pg_current_snapshot()` returns the active snapshot of the poll statement, so "visible now" and the stored cursor agree. (2) A row is fed iff its writer committed before the current snapshot and was not visible in the previous one: `txid ≥ xmax(prev)` or `txid ∈ xip(prev)`. The `txid >= xmin(prev)` term only narrows the index scan, because anything below `xmin(prev)` was visible before. (3) `pg_current_xact_id()` is the top-level xid, and snapshots list top-level xids, so subtransaction writes behave correctly (proven). (4) `xid8` is epoch-extended 64-bit: there is no wraparound, and freezing does not touch a stored column value. (5) A long-running writer is fed exactly once when it commits (proven). Hub version dedupe also makes a re-read harmless. (6) Rows from before 0004 (`txid NULL`) are never fed, which is fine because they predate the feed. Residuals (cost under a pinned xmin, xid regression after restore or failover) are in RV5R-03. |
| Polling with no subscribers | **ACCEPTED.** That is 2 statements/s. In steady state the feed statement uses `job_events_txid_idx` in both the custom and the generic plan (D8: 0.006 ms). Polling always is the price of not missing commits around a subscribe. |
| Auth-failure bucket per peer only | **ACCEPTED.** The key is `RemoteAddr` (X-Forwarded-For is not trusted, so the key cannot be spoofed). Only forgery signals count (`token_invalid`, `assertion_invalid`; gRPC: unknown, malformed or missing secret), and a verified credential is never refused. Behind the BFF, a guesser exhausts the BFF peer's bucket, so other *invalid* requests get 429 instead of 401, which is harmless. Distributed guessing is not limited globally: with 256-bit secrets that is infeasible, and the per-request cost is one lookup or one Ed25519 verify. The gRPC "lifecycle reasons are not charged" rule has no test (R06 survives, RV5R-04). |
| Denial-audit budget as constants (1/s, burst 60, per credential, in-process) | **ACCEPTED.** It is documented in ADR-0004 and state-machine.md. The limiter tracks at most 10 000 keys and fails toward "not audited", never toward "not answered". Recommended: a counter of suppressed rows (e.g. `clusterx_worker_denial_audit_suppressed_total`), so that suppression is itself observable. The budget does not cover the takeover audit (RV5R-02). |
